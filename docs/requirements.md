# peek — 要件定義

ユーザとのヒアリング結果をもとにまとめた要件。**設計の一次ソース**。
議論履歴は元の Claude Code セッションにあり、ここでは結論のみ記載する。

## 1. 背景・目的

既存ツール（lazygit / difit）への不満を起点として、自作に至った。

### 既存ツールの不満点

- **lazygit**: TUI の雰囲気が強すぎる（`+` / `-` 記号、レトロな見た目）。もう少しリッチな UI が欲しい。ただしアプリケーション化は不要
- **difit**: GitHub PR ビューに寄り過ぎている／ブラウザを開くのが嫌／worktree 非対応

### メインのユースケース

1. **AI エージェントが書いたコードのレビュー**
2. **複数 worktree を行き来しながらの作業**

副次的なシーン（コミット前チェック、他人の PR レビュー）は今回の対象外。

## 2. 機能要件

### 2.1 ファイルツリー（左ペイン）

- **デフォルト**: プロジェクト全体のツリー表示 + 変更マーカー（M / A / D / R / ?）
- **トグル**: キー押下で「変更のあるファイルだけのフラットリスト」に切替可能
- **フィルタ**: ツリー内のクイックファジー検索
- `.gitignore` を尊重

### 2.2 右ペイン（ファイルビュー）

モードを 3 つ持つ:

- **View**: 読み取り専用のコードビュー（シンタックスハイライト付き、スクロール可）
- **Edit**: 簡易編集（テキスト修正・保存のみ。LSP 連携や Code Jump は**不要**）
- **SplitDiff**: HEAD とワーキングツリーの side-by-side 2 カラム表示

変更ありのファイルを選択したときのデフォルトは **SplitDiff**、変更なしは **View**。
ユーザがキーで **View ↔ SplitDiff** を切替できる。

### 2.3 worktree

- **一覧表示と切替のみ**（追加・削除・worktree 間の差分比較は**不要**）
- 同時に複数 worktree を一画面で表示する機能は**不要**（名前さえ一覧で見られればよい）
- 切替は **モーダル/パレット**（IntelliJ のアクション呼び出し的）
- 切替時の「ファイル位置の引き継ぎ」は**不要**（リセットでよい）

### 2.4 検索

実装すべき検索は以下 3 種:

- **ファイル名検索** — IntelliJ の `⌘⇧O` 相当のフジィ検索
- **ファイル内検索** — 開いているファイル/diff の中の検索（`⌘F` 相当）
- **プロジェクト全文検索** — 全ファイルに対する grep（`⌘⇧F` 相当）

「diff 行のみに絞った検索」は**不要**。

### 2.5 キーバインド（IntelliJ 風）

ターミナル制約により `⌘` は使えず **Ctrl ベース**に寄せる。IntelliJ ユーザが迷わない対応表は `design.md` 参照。

ユーザが明示的に要望したもの:

- ツール切替（⌘1 / ⌘2 相当）
- Recent Files（⌘E 相当）
- プロジェクト全文検索（⌘⇧F 相当）
- ファイル名フジィ検索（⌘⇧O 相当）
- 開いているファイルのパスをコピー（⌘⇧C 相当）
- 現在のファイル/diff 内検索（⌘F 相当）
- モーダル/検索を閉じる（Esc）

### 2.6 git 操作（2026-04 更新）

当初は「git 操作自体は AI エージェントが行う」前提だったが、ユーザ要望により peek から以下を可能にする:

- **コミット履歴**: 現ブランチの直列ログ表示
- **コミット単位の SplitDiff**: 選択した commit の変更ファイル一覧 → ファイル選択で parent 対 commit の SplitDiff
- **ブランチ切替**: `git switch`。ワーキングツリーが dirty なら確認ダイアログ
- **blame**: 現在開いているファイルの blame を右ペインに表示（View ↔ Blame をキーでトグル）

ただし **履歴を書き換える操作は peek では扱わない**: commit / push / pull / fetch / rebase / merge / cherry-pick / stash / branch 作成・削除 等は引き続き AI エージェント側の責務。

## 3. 非機能要件

- **軽量**: 起動 < 1 秒、大規模リポジトリでも応答性維持
- **永続化**: 閲覧済みファイルのマーキングや再起動後の状態保持は**不要**
- **設定**: 将来的にキーマップ等を `~/.config/peek/` 配下で上書き可能にする（MVP では不要）
- **プラットフォーム**: macOS 中心（Linux でも動くこと。Windows は優先しない）

## 4. 対象外（明示的に不要）

以下は **ユーザが不要と明言した**機能。実装しない。

- diff へのコメント機能 / AI プロンプトとしてコピーする機能（difit の機能）
- 閲覧済みマーカー・永続化
- worktree の追加・削除・間の差分比較
- 複数 worktree 同時表示
- Code Jump / LSP 機能
- 履歴を書き換える git 操作（commit / push / pull / rebase / merge / branch 作成・削除 / stash 等）
- PR 連携機能

## 5. ツール名

**`peek`**（短く、用途を直感的に伝える、CLI 名として打鍵しやすい）

## 6. 配布方針

- 当面は自分専用
- 将来的に OSS 公開の可能性あり（現時点で判断保留）
